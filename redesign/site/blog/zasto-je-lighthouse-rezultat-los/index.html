Kako je moguće da je rezultat toliko loš kada meni web radi brzo?

Odgovor je jednostavan.

Vaš subjektivni osjećaj brzine i Lighthouse test ne mjere potpuno istu stvar.

Na vlastitom računalu možda imate:

  • brz procesor
  • brzu internetsku vezu
  • već cacheirane resurse
  • prethodno učitane fontove
  • moderan browser

Lighthouse pokušava web analizirati u kontroliranijim i često zahtjevnijim uvjetima.

Zato nizak rezultat ne mora značiti da je web potpuno spor.

Ali isto tako ne treba automatski zaključiti da Lighthouse “nije bitan”.

Loš rezultat vrlo često otkrije tehničke probleme koje na vlastitom uređaju jednostavno ne primjećujete.

Što je Lighthouse?

Lighthouse je alat za automatsku analizu web stranice.

Može analizirati nekoliko područja, među kojima su:

  • performance
  • accessibility
  • best practices
  • SEO

Kod performansi pokušava procijeniti koliko kvalitetno stranica radi u određenim testnim uvjetima.

Ne gleda samo:

koliko sekundi je trajao download cijele stranice.

Analizira različite dijelove iskustva.

Primjerice:

  • kada korisnik vidi glavni sadržaj
  • koliko se stranica blokira
  • pomiče li se layout
  • koliko JavaScripta browser mora obraditi

Zato Performance rezultat nije običan timer.

Lab test

Lighthouse koristi laboratorijsko testiranje.

To znači da se web testira u kontroliranim uvjetima.

To je korisno jer test možemo ponavljati i uspoređivati rezultate.

Primjer:

Prije optimizacije:

Performance 58

Nakon optimizacije hero slike:

Performance 76

Možemo vidjeti da je promjena imala pozitivan utjecaj.

Ali lab test nije isto što i iskustvo svakog stvarnog korisnika.

Vaš uređaj nije prosjek

Vaše računalo možda ima:

  • snažan CPU
  • 32 GB RAM-a
  • gigabitni internet
  • dobar Wi-Fi

Korisnik može imati:

  • nekoliko godina star Android
  • slabiji procesor
  • mobilnu mrežu
  • nizak signal

JavaScript koji vaše računalo obradi gotovo trenutno na slabijem uređaju može predstavljati puno veći problem.

Cache vara

Postoji još jedan razlog zašto vam vlastiti web često djeluje posebno brz.

Već ste ga otvorili.

Browser možda već ima cacheirane:

  • CSS datoteke
  • JavaScript
  • fontove
  • logo
  • slike

Kod sljedećeg posjeta ne mora ih sve ponovno preuzimati.

Novi korisnik nema tu prednost.

Njegov prvi posjet često je puno važniji za performance analizu.

Prvi posjet

Zamislimo potencijalnog klijenta koji na Googleu pronađe vašu stranicu.

To je njegov prvi posjet.

Browser nema:

  • vaš font
  • CSS
  • JavaScript
  • slike

Sve mora dobiti prvi put.

Upravo taj trenutak treba biti kvalitetan.

Ne samo ponovno otvaranje weba na računalu osobe koja ga je razvila.

Zato ne treba optimizirati broj.

što uzrokuje loš broj?

Moguće je da web ima:

  • odličan server

Drugi web može imati potpuno suprotan problem.

Oba mogu završiti s približno sličnim ukupnim rezultatom.

Rješenje nije isto.

LCP

Jedna od važnih stvari koju ćete susresti je Largest Contentful Paint.

LCP promatra koliko brzo korisnik dobiva glavni veliki sadržaj u početnom prikazu.

To često može biti:

  • hero fotografija
  • veliki naslov
  • glavni vizual

Ako je ostatak stranice brz, ali se hero fotografija od nekoliko megabajta dugo učitava, Lighthouse će to primijetiti.

Vama web možda djeluje dovoljno brz jer su:

  • navigacija
  • pozadina
  • tekst

već vidljivi.

Ali glavni element još kasni.

Detaljnije smo ovu metriku objasnili u vodiču što su Core Web Vitals.

CLS

Drugi problem može biti stabilnost layouta.

Stranica se možda učita brzo, ali elementi tijekom učitavanja skaču.

Primjer:

H1 se pojavi.

Nakon toga se učita font.

Naslov postane širi.

Prelomi se u dodatni red.

Sve ispod njega pomakne se prema dolje.

Stranica nije nužno spora.

Ali iskustvo nije potpuno stabilno.

Lighthouse može takve stvari lakše otkriti nego korisnik koji samo površno pogleda vrijeme učitavanja.

JavaScript

Jedan od najvećih razloga za razliku između:

web izgleda brzo

i:

Lighthouse score je loš

može biti JavaScript.

Stranica se vizualno pojavi.

Ali browser u pozadini još obrađuje veliku količinu koda.

To može utjecati na:

  • interakciju
  • gumbe
  • menu
  • forme
  • animacije

Na snažnom računalu možda nećete primijetiti ništa.

Na slabijem mobitelu razlika može biti značajna.

Main thread

Browser velik dio posla obavlja na glavnom threadu.

Ako je on zauzet dugim zadatkom, druge stvari moraju čekati.

Primjer:

Browser obrađuje veliku JavaScript skriptu.

Korisnik klikne hamburger menu.

Klik se dogodio, ali browser još nije spreman obraditi reakciju.

Korisnik osjeća kašnjenje.

To je jedan od razloga zašto web može biti vizualno učitan, ali još ne djelovati potpuno responzivno.

Veliki bundle

Kod Reacta i drugih JavaScript frameworka lako se može proizvesti velik bundle.

U njemu možda završavaju:

  • komponente
  • biblioteke
  • utilityji
  • animacije
  • kod koji korisniku još nije potreban

Browser taj kod mora:

  1. preuzeti
  2. parsirati
  3. obraditi
  4. izvršiti

Zato veličina JavaScripta nije samo pitanje kilobajta.

Postoji i CPU trošak.

Unused JavaScript

Lighthouse često prijavljuje unused JavaScript.

To znači da je korisnik preuzeo određeni kod koji nije bio potreban za trenutni prikaz stranice.

Primjer:

Na početnoj stranici učitava se kod za:

  • kompleksnu galeriju
  • booking calendar
  • chart biblioteku

iako nijedan od tih elemenata nije trenutno prikazan.

To je nepotreban teret.

Rješenje može biti:

  • code splitting
  • dynamic import
  • uvjetno učitavanje

ovisno o tehnologiji.

WordPress ima isti problem

Problem nije rezerviran samo za React.

WordPress plugin može učitati svoj CSS i JavaScript na svakoj stranici.

Primjer:

Plugin za contact formu koristi se samo na /kontakt/.

Ali njegov CSS i JS učitavaju se i na:

  • naslovnoj
  • blogu
  • uslugama
  • projektima

Ako nekoliko pluginova radi isto, brzo se nakupi dosta nepotrebnih resursa.

Third-party skripte

To su vanjski servisi.

Primjer:

  • Google Analytics
  • Google Tag Manager
  • Meta Pixel
  • Microsoft Clarity
  • chat widget
  • cookie consent
  • Hotjar
  • remarketing
  • embedded video

Svaki od tih alata može biti poslovno opravdan.

Ali zajedno imaju cijenu.

Treba procijeniti:

Trebamo li stvarno sve što se učitava?

Tag Manager

Google Tag Manager je vrlo praktičan.

Ali može postati mjesto gdje se godinama dodaju novi tagovi bez čišćenja starih.

Web developer možda optimizira stranicu do detalja.

A nakon toga GTM učita:

  • nekoliko analytics alata
  • advertising skripte
  • heatmap
  • tracking koji se više ne koristi

Zato performance audit treba uključiti i marketinški tracking setup.

Cookie alat

Cookie consent također može imati performance trošak.

Posebno ako koristi kompleksan vanjski sustav.

To ne znači da ga treba ukloniti ako je potreban.

Ali vrijedi provjeriti:

  • koliko skripti dodaje
  • kada ih učitava
  • blokira li sadržaj
  • postoje li nepotrebne integracije

Compliance funkcionalnost također treba kvalitetno implementirati.

Chat widget

Chat je još jedan dobar primjer.

Može biti vrijedan poslovni alat.

Ali neki chat widgeti učitavaju značajnu količinu:

  • JavaScripta
  • CSS-a
  • fontova
  • dodatnih requestova

Ako gotovo nitko ne koristi chat, treba razmotriti je li njegova poslovna vrijednost dovoljna za cijenu koju svaki posjetitelj plaća.

Slike

Lighthouse score vrlo često ruše slike.

To može biti zbog:

  • prevelikih dimenzija
  • lošeg formata
  • nedovoljne kompresije
  • pogrešne responsive verzije
  • načina učitavanja

Web na vašoj brzoj vezi može otvoriti sliku od 2 MB vrlo brzo.

Simulirani mobilni korisnik neće nužno imati isto iskustvo.

Zato smo pripremili zaseban vodič o optimizaciji slika za web.

Hero slika

Hero slika posebno često utječe na Lighthouse.

Razlog je jednostavan.

Ona je:

  • velika
  • odmah vidljiva
  • često LCP element

Ako koristite:

3840 × 2160 fotografiju

za prikaz od približno 1200 px, šaljete nepotrebno veliku datoteku.

Ako uz to koristite lazy loading na hero slici, rezultat može biti još lošiji.

Fontovi

Fontovi također mogu biti dio problema.

Primjer:

Web učitava:

  • dva font familyja
  • šest weightova svakog
  • italic verzije

To može značiti velik broj dodatnih fileova.

Fontovi također mogu uzrokovati pomicanje sadržaja nakon učitavanja.

Zato treba optimizirati:

  • broj familyja
  • weightove
  • format
  • preload
  • fallback

Detaljnije smo to obradili u članku kako fontovi utječu na brzinu weba.

Hosting

Nizak Lighthouse rezultat ne znači automatski da trebate promijeniti hosting.

Ali spor serverski odgovor može biti početak problema.

Ako server dugo čeka prije nego što počne vraćati stranicu, svi frontend resursi kreću kasnije.

Možete savršeno optimizirati slike.

Ako HTML dolazi presporo, ukupno iskustvo i dalje pati.

Više o tome pročitajte u vodiču zašto je dobar hosting važan.

Render-blocking resursi

Browser ne može uvijek odmah prikazati sadržaj.

Određeni CSS i JavaScript resursi mogu blokirati renderiranje dok se ne preuzmu i obrade.

Zato Lighthouse može prijaviti render-blocking resources.

To ne znači:

uklonite sav CSS.

Znači da treba provjeriti:

  • treba li taj resurs odmah
  • koliko je velik
  • može li se drugačije učitati

CSS

Veliki CSS file može sadržavati ogroman broj stilova koji trenutnoj stranici nisu potrebni.

To se često događa kod:

  • frameworka
  • page buildera
  • velikih tema
  • pluginova

Ako web koristi samo mali dio svih dostupnih komponenti, korisnik možda svejedno dobiva stilove za cijeli sustav.

To nije uvijek jednostavno riješiti.

Ali vrijedi razumjeti gdje trošak nastaje.

DOM

Lighthouse može upozoriti i na vrlo velik DOM.

Jednostavna vizualna sekcija možda u HTML-u nije tako jednostavna.

Page builder može proizvesti:

Section
└── Wrapper
    └── Container
        └── Inner
            └── Column
                └── Wrapper
                    └── Content

Ako to ponovite stotinama puta, DOM postaje velik.

Browser mora održavati cijelu tu strukturu.

Builder nije automatski problem

Važno je ne zaključiti:

Page builder = spor web.

To nije nužno točno.

Dobar builder web može biti vrlo brz.

Ali builder olakšava dodavanje:

  • sekcija
  • efekata
  • wrappera
  • pluginova

pa je lakše izgraditi nepotrebno kompleksnu stranicu.

Problem je način korištenja alata, ne samo alat.

Animacije

Animacije također mogu utjecati na rezultat.

Posebno kompleksne scroll animacije i efekti koji traže puno JavaScripta.

Ako imate:

Produkcija i lokalno

Development build može imati:

Ekstenzije

Kod lokalnog Lighthouse testa browser ekstenzije također mogu utjecati na okruženje.

PageSpeed i Lighthouse

Ova dva pojma često se koriste kao sinonimi, ali nisu potpuno ista stvar.

Lighthouse je audit engine.

PageSpeed Insights koristi Lighthouse za laboratorijski dio analize, ali može prikazati i podatke stvarnih korisnika kada su dostupni.

Zato PageSpeed stranica može pokazati:

  • stvarno korisničko iskustvo
  • laboratorijski test

i ta dva rezultata se mogu razlikovati.

To nije kontradikcija.

Mjere različite stvari.

Field podaci

Ako web ima dovoljno stvarnog prometa, field podaci mogu biti posebno vrijedni.

Dobar rezultat

Ne postoji jedan Lighthouse broj koji bi svaki web morao postići pod svaku cijenu.

Važnije je:

  • postoje li ozbiljni problemi
  • kakvi su Core Web Vitals
  • kako web radi na stvarnim uređajima
  • postoji li nepotreban tehnički teret

Web s vrlo dobrim iskustvom i rezultatom u visokim 80-ima ili 90-ima ne treba nužno radikalan zahvat samo zbog nekoliko preostalih bodova.

Web s rezultatom 40 i velikim tehničkim problemima zaslužuje ozbiljniju analizu.
